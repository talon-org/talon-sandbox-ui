## Overview

`Dialog` renders a centered modal overlay with a title, body, optional footer, focus trap, and Escape / backdrop dismiss. Use it for confirmations, short forms, and critical decisions that require the user to resolve before continuing.

### When to use vs Drawer

| | Dialog | Drawer |
|--|--------|--------|
| **Content type** | Confirmations, short forms | Detail panels, longer forms |
| **Interruption** | Blocks the page | Slides in alongside content |
| **Width** | Fixed narrow/medium | Configurable, typically 400–640px |
| **Example** | "Delete sandbox?" confirm | Sandbox detail / edit form |

## Keyboard behavior

| Key | Effect |
|-----|--------|
| `Escape` | Close dialog |
| `Tab` / `Shift+Tab` | Cycle focus within dialog (trapped) |

## Accessibility

- Uses `role="dialog"` with `aria-modal="true"` and `aria-labelledby` pointing at the title element — screen readers announce the dialog name when it opens.
- `useFocusTrap` keeps focus inside the dialog while it is open.
- The close button has `aria-label="Close dialog"`.
- Clicking the backdrop calls `onClose` — this is standard expected behavior per ARIA patterns.
- Do not put scrollable content in the body without a max-height and `overflow-y: auto` wrapper — the dialog itself does not enforce scroll by default.
