# Input

Single-line text control. Extends the native `<input>` element with design-system sizing, invalid state, monospace mode, and prefix/suffix adornments.

## When to use

- Single-line free-text entry: names, IDs, URLs, search queries.
- For multi-line content use `Textarea`.
- For numeric values use `NumberInput` (when available) — it handles step/clamp/stepper buttons.
- For selection from a list use `Select`, `MultiSelect`, or `Combobox`.

## When NOT to use

- Do not use bare `<input>` in application code — always use this component so sizing and token styling are applied consistently.
- Do not place a label directly inside the `prefix` slot — the `prefix` slot is for icons and adornments only. Use `FormField` for label + input composition.

## Anatomy

```
[prefix slot] [input] [suffix slot]
```

When neither `prefix` nor `suffix` is present, the `<input>` element is the root element.
When either is present, a `.tln-input-wrap` div wraps all three.

## Keyboard behavior

Inherits native `<input>` keyboard behavior. No custom keyboard handling.

  );

## Gotchas

- `className` is applied to the **outermost element**: the `<input>` when no adornments are present, or the `.tln-input-wrap` div when adornments are present. This means width/margin classes on `className` work correctly in both cases.
- When using `prefix`/`suffix`, the inner `<input>` does NOT receive `className`. Target it via `.tln-input-wrap > .tln-input` if needed.

## Accessibility checklist

- Always associate an `<input>` with a label via `<label htmlFor>` or `aria-label` — use `FormField` for the former.
- `invalid` sets `aria-invalid="true"` on the input.
- Prefix/suffix adornments are wrapped in `<span>` — if they contain interactive elements, ensure those elements have their own accessible names.
