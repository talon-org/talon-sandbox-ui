# Switch

Accessible on/off toggle using `role="switch"`. Designed for binary settings that take immediate effect.

## When to use vs Checkbox vs Toggle

| Component | Best for |
|-----------|---------|
| **Switch** | Settings that take **immediate effect** on toggle — no "Save" button required. Examples: "Enable debug logging", "Pause sandbox on idle". The visual metaphor communicates instantaneous change. |
| **Checkbox** (coming) | Form fields inside a form where state is **submitted together** — e.g. "Accept terms", "Notify me". State is collected at submit time, not applied immediately. Also correct for "select all" in a table. |
| **Segmented** | Choosing between more than two mutually exclusive modes — e.g. Dark / Light / System. |

Use Switch when the label describes a feature that is simply on or off and the user expects the change to happen right now.

## Anatomy

```
role="switch" aria-checked={checked}
  [hidden <input type="checkbox"> for form submission]
  [.knob]
```

## Keyboard behavior

| Key | Effect |
|-----|--------|
| `Space` | Toggles the switch |
| `Enter` | Toggles the switch |
| `Tab` | Moves focus to next focusable element |

## Examples

### Default (controlled)

export const Default = () => {
  const [on, setOn] = useState(false);
  return (
    <div style={{ padding: 16, display: 'flex', alignItems: 'center', gap: 12 }}>
      <Switch checked={on} onChange={setOn} />
      <span style={{ color: 'var(--fg-2)', fontSize: 13 }}>{on ? 'Enabled' : 'Disabled'}</span>
    </div>
  );
};

## Accessibility checklist

- The switch element uses `role="switch"` and `aria-checked` — screen readers announce "on"/"off" automatically.
- The `name` + `value` props render a hidden `<input type="checkbox">` for native form data collection.
- Always pair with a visible label — either a sibling element (as in SettingsList above) or `aria-label`.
- Disabled state uses `aria-disabled` (not the HTML `disabled` attribute) to keep the element reachable for screen readers.
