# Button

The primary interactive control. Use `Button` for actions that trigger navigation, submit forms, or execute commands.

## When to use

- Use `variant="primary"` for the single most important action on a screen (create, submit, confirm). Limit to one primary button per view.
- Use `variant="default"` for secondary actions that are still important but not the primary CTA.
- Use `variant="ghost"` for low-emphasis actions: cancel, dismiss, navigate back.
- Use `variant="danger"` for irreversible destructive actions (delete, revoke). Pair with a confirmation dialog.
- Use `iconOnly` for toolbar actions where space is constrained — always supply an `aria-label`.

## When NOT to use

- Do not use Button for navigation that changes the URL — prefer `<a>` elements.
- Do not use multiple `primary` buttons on the same screen.
- Do not use `danger` for soft/reversible actions.

## Anatomy

```
[optional kbd hint]
[  children content  ]
```

For icon-only: `[icon]` with `iconOnly` prop and `aria-label`.

## Keyboard behavior

| Key | Effect |
|-----|--------|
| `Space` / `Enter` | Activates the button |
| `Tab` | Moves focus to next focusable element |
| `Shift+Tab` | Moves focus to previous focusable element |

## Accessibility checklist

- Always supply visible text content or `aria-label` for icon-only buttons
- `loading` buttons automatically set `aria-busy="true"` and `disabled`
- `type="button"` is set by default — explicit `type="submit"` required inside forms
- Avoid `onClick` on non-interactive wrappers — use `<Button>` directly
