# TerminalChrome

Top chrome bar and bottom status bar for a terminal/sandbox view. Wrap your terminal emulator (xterm.js, etc.) as `children`. Does not render a terminal — it provides the surrounding UI chrome.

## When to use

- Wrapping a real terminal emulator inside the Talon Sandbox console.
- Any full-screen or panel-style code/terminal UI that needs a standard header with sandbox ID, recording controls, and a status footer.

## When NOT to use

- Don't use TerminalChrome to wrap arbitrary non-terminal content — use `Card` or `Panel` for general content areas.

## Anatomy

```
[.tln-term-chrome]
  [.tln-term-chrome__top]
    [back button — optional]
    [.tln-term-chrome__info — dot + id + name]
    [.tln-term-chrome__actions — record button + topActions slot]
  [.tln-term-chrome__body]   ← children (your terminal)
  [.tln-term-chrome__bot]    ← bottomStatus slot (optional)
```

## Accessibility checklist

- The "back" button is a native `<button>` — no additional ARIA needed.
- The "Record" / "Recording" button is a native `<button>` — label changes on state.
- `topActions` slot accepts any ReactNode — ensure any interactive elements in that slot have accessible names.
- The terminal body (`children`) is responsible for its own accessibility (xterm.js has `aria-live` support).
