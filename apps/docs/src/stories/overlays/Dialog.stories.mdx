# Dialog

Modal dialog with focus trap, backdrop click-to-close, and Escape-to-close. Renders into a portal at `document.body`.

## When to use

- Confirmations for destructive or high-impact actions (delete, revoke, force-stop).
- Short focused tasks that don't need a full page: rename a resource, enter a required token, confirm billing.
- Informational modals that the user must acknowledge before proceeding.

## When NOT to use

- Forms with many fields — use a `Drawer` (side sheet) instead, which has more vertical space and feels less constrained.
- Long workflows with multiple steps — each step should be its own page or route.
- Non-blocking notifications — use `Toast`.

## Anatomy

```
[backdrop — click to close]
  role="dialog" aria-modal="true" aria-labelledby={titleId}
    [.tln-dialog-head]
      [h3#titleId]     ← title prop
      [close button]
    [.tln-dialog-body] ← children prop
    [.tln-dialog-foot] ← footer prop (optional)
```

## Keyboard behavior

| Key | Effect |
|-----|--------|
| `Escape` | Closes the dialog |
| `Tab` | Cycles through focusable elements inside the dialog (focus trap) |
| `Shift+Tab` | Cycles backwards |

## Examples

### Confirmation dialog

export const Confirmation = () => {
  const [open, setOpen] = useState(false);
  return (
    <div style={{ padding: 16 }}>
      <Button variant="danger" onClick={() => setOpen(true)}>Delete sandbox</Button>
      <Dialog
        open={open}
        onClose={() => setOpen(false)}
        title="Delete sandbox?"
        footer={
          <div style={{ display: 'flex', gap: 8, justifyContent: 'flex-end' }}>
            <Button variant="ghost" onClick={() => setOpen(false)}>Cancel</Button>
            <Button variant="danger" onClick={() => { alert('deleted'); setOpen(false); }}>Delete</Button>
          </div>
        }
      >
        <p style={{ margin: 0, color: 'var(--fg-2)', fontSize: 13, lineHeight: 1.6 }}>
          This will permanently destroy <strong>sb-prod-01</strong> and all its data.
          This action cannot be undone.
        </p>
      </Dialog>
    </div>
  );
};

### Input dialog

export const InputDialog = () => {
  const [open, setOpen] = useState(false);
  const [name, setName] = useState('');
  return (
    <div style={{ padding: 16 }}>
      <Button onClick={() => setOpen(true)}>Rename</Button>
      <Dialog
        open={open}
        onClose={() => setOpen(false)}
        title="Rename sandbox"
        footer={
          <div style={{ display: 'flex', gap: 8, justifyContent: 'flex-end' }}>
            <Button variant="ghost" onClick={() => setOpen(false)}>Cancel</Button>
            <Button variant="primary" onClick={() => { alert(`renamed to: ${name}`); setOpen(false); }}>
              Save
            </Button>
          </div>
        }
      >
        <div style={{ display: 'flex', flexDirection: 'column', gap: 6 }}>
          <label htmlFor="rename-input" style={{ fontSize: 11, textTransform: 'uppercase', letterSpacing: '0.06em', color: 'var(--fg-3)' }}>
            New name
          </label>
          <Input
            id="rename-input"
            value={name}
            onChange={e => setName(e.target.value)}
            placeholder="my-sandbox"
          />
        </div>
      </Dialog>
    </div>
  );
};

## Gotchas

- The dialog renders nothing when `open` is `false` — no hidden DOM node.
- The close button in the header calls `onClose`. Your state update must actually flip `open` to `false` — the component does not manage open state internally.
- Click on the backdrop calls `onClose`. Prevent this in the footer's confirm handler if your form has validation — close only after validation passes.

## Accessibility checklist

- `role="dialog"` and `aria-modal="true"` are set automatically.
- `aria-labelledby` is wired to the `title` prop via `useId()` — no manual ID needed.
- Focus trap prevents Tab from leaving the dialog while open.
- Escape closes the dialog (calls `onClose`).
- When the dialog opens, focus moves to the first focusable element inside it (via `useFocusTrap`).
- When the dialog closes, focus should return to the trigger button — this is the caller's responsibility.
