# Tokens Overview

`@talon-sandbox/tokens` uses CSS custom properties throughout. Colour tokens are generated by an OKLCh algorithm; non-colour tokens are authored manually and stay stable across all themes.

---

## Three-layer model

```
OKLCh anchors  ─→  7-step ladder  ─→  bridge tokens
(perceptually uniform anchors)  (7-stop ramp)  (--acc / --bg-1 semantic aliases)
```

**Layer 1: OKLCh anchors**

Each hue is defined by a lightness, chroma, and hue angle in the OKLCh perceptually uniform colour space. `theme-gen.js` derives seven stops from the anchor. The algorithm ensures consistent perceived contrast between stops in both dark and light mode.

**Layer 2: 7-step ladder**

Each hue produces seven stops:

| Stop | Semantic use |
|---|---|
| `1` | Darkest tinted background — selected row / chip fill |
| `2` | Second-darkest background |
| `3` | Darker — border / emphasis background |
| `4` | Mid — high-contrast border |
| `5` | Solid primary (solid buttons, status badges) |
| `6` | Hover state |
| `7` | Text on `--bg-1` background |

**Layer 3: bridge tokens**

Wrap the ramp into semantic aliases. Component code only references bridge tokens; changing the theme requires zero component changes:

```css
--acc        → step 5 of the current accent hue
--acc-soft   → steps 1–2 (chip / tinted background)
--acc-line   → steps 3–4 (borders)
--acc-strong → step 7 (text / hover emphasis)
--bg-1, --fg-1, --line … (surface, text, divider)
```

## Orthogonal switches

Four independent dimensions set on `<html>`, freely composable:

| Attribute | Values | Default | Effect |
|---|---|---|---|
| `data-mode` | `light` | (none = dark) | Dark / light |
| `data-theme` | `onyx` `pewter` `iron` `phosphor` `indigo` `violet` `sky` `teal` | (none = ink) | Accent hue |
| `data-density` | `compact` `relaxed` | (none = standard) | Control heights / padding |
| `data-font` | `plex` `jetbrains` `system` | (none = geist) | Font family |

```html
<!-- Example: light mode + onyx theme + compact density -->
<html data-mode="light" data-theme="onyx" data-density="compact">
```

## Colour token groups

| Group | Prefix | Purpose |
|---|---|---|
| Surfaces | `--bg-0` … `--bg-4` `--bg-input` `--bg-hover` `--bg-active` | Background levels |
| Text | `--fg-0` … `--fg-4` | Text contrast steps |
| Lines | `--line-soft` `--line` `--line-strong` `--line-emphasis` | Alpha-based dividers |
| Accent | `--acc` `--acc-1..7` `--acc-fg` `--acc-soft` `--acc-line` `--acc-strong` `--acc-dim` | Brand hue system |
| Status | `--ok` `--warn` `--err` `--info` `--magenta` `--teal` each with `-1..7` `-soft` `-line` `-strong` `-dim` | Semantically fixed |

## Authoring rules

1. **No literal colour values** — components reference CSS variables only, never hex literals.
2. **Prefer bridge tokens** — consume `--acc` / `--bg-1` / `--fg-1`, not `--acc-5` / `--gray-2`.
3. **Status colours are for status** — `--ok/warn/err/info` are not decorative brand colours.
4. **Theme via attributes** — do not write per-theme or per-mode CSS rules; drive them with `data-mode` / `data-theme`.
5. **Spacing uses `--s-*`, flex/grid uses `gap`** — avoid margin stacking for spacing.
